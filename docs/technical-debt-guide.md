# Technical Debt Guide

## Record real consequences

Technical debt is useful when connected to risk, delay, maintenance cost,
quality, or strategic limitation.

## Avoid the junk drawer

Not every improvement is technical debt.

## Prioritize by impact

Age alone does not define urgency. Consider user impact, failure risk, cost of
delay, and remediation opportunity.

## Close with evidence

A debt item is complete when the harmful condition is removed or intentionally
reclassified.
