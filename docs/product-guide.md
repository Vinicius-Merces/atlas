# Product Guide

## Start with the problem

A feature request may be a proposed solution rather than the true user need.
Clarify the problem, affected users, desired change, and constraints before
locking scope.

## Define outcomes

An outcome describes a change in user, business, or system behavior. An output
describes what was built.

## Bound scope

Clear non-goals protect delivery from accidental expansion.

## Measure learning

Metrics should support decisions. Avoid vanity metrics without a defined use.
