# Enterprise Architecture Guide

## Model capabilities, not only applications

Applications change. Business and technical capabilities provide a more stable
view of where duplication, gaps, and strategic dependencies exist.

## Use transition states

Target architecture without a migration path is an aspiration, not a plan.

## Rationalize intentionally

Invest, migrate, consolidate, contain, and retire are different actions. Each
requires explicit ownership and evidence.

## Govern interfaces

Cross-domain APIs, data ownership, identity, platforms, and operational
responsibility need stronger clarity than internal implementation details.
