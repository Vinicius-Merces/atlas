- **Purpose:** Preserve evidence-based continuity and completion lessons.
- **Scope:** Cross-project delivery, checkpoints and outcome validation.
- **Owner:** ATLAS maintainer
- **Source of truth:** `docs/project-delivery-feedback.md`, `reports/atlas-effectiveness-2026-10-16.md`, `scripts/validate_continuity_state.py`
- **Last reviewed:** 2026-10-16
- **Related contracts or ADRs:** `.claude/contracts/memory-contract.md`, `.claude/contracts/workflow-contract.md`

## Reusable rules

- A passing framework suite proves conformance, not product acceptance.
- Preserve session risks, next action and pending work in the resume packet.
- Active continuity must match VERSION and reference actual canonical artifacts.
- Save validated repetitive batches with exact completed and remaining IDs.
- Report remote persistence and deployment separately from local implementation.
- Visual approval requires verification of the exact integrated asset in context.
- Use applicable product flow checks; report unavailable runtime checks honestly.
- Learn from historical defect reports without assuming they remain open today.

## Change triggers

Review when checkpoint loss recurs, completion claims lack evidence, or active
continuity fails to describe current repository state.
