# Beta Stabilization Workflow

## Trigger

A release or change targets the `0.1.0-beta.x` line.

## Sequence

1. Identify stable contracts and paths affected.
2. Run semantic compatibility verification.
3. Run package, smoke, and contract tests.
4. Review documentation and migration needs.
5. Update support and compatibility matrices.
6. Review deprecations.
7. Record known limitations.
8. Produce release confidence assessment.
9. Approve, conditionally approve, or block.
