# Generative Engine Optimization Delivery

## Trigger
Use for a material GEO or AI-search visibility initiative that changes entity evidence, answer-ready content, information architecture, structured data, discoverability, authority strategy, or measurement. Do not use for an isolated metadata edit with no broader GEO impact.

## Objective
Deliver evidence-backed GEO improvements that make authoritative public information easier for people, crawlers, and AI answer systems to discover, verify, understand, cite, and navigate without weakening normal SEO, accessibility, privacy, localization, or factual product truth.

## Inputs
Required:
- project memory, business goal, target market/locale, audiences, and priority questions;
- canonical entity/product/service facts and accountable owners;
- rendered routes, internal-link structure, SEO/schema state, and content inventory;
- available Search Console, analytics, conversion, indexation, and prior AI-search observation evidence.

Optional:
- current official platform guidance, third-party citations, directories, press, research, community references, and prior GEO experiments.

## Responsible agents
- `generative-engine-optimization-strategist` owns GEO strategy, evidence standards, prioritization, and measurement interpretation.
- SEO, structured-data, content, analytics, localization, accessibility, privacy, security, and product specialists remain authoritative for their own contracts.
- `generative-engine-optimization-review` provides independent review before material GEO approval.

## Sequence
1. Understand: load project memory, business outcomes, target audience/market, canonical facts, and current evidence.
2. Inspect: map entities with `entity-authority-mapping`; inspect rendered discoverability, technical SEO, structured data, internal links, localization, accessibility, authority evidence, and measurement state.
3. Plan: identify answer gaps, conflicting claims, authority gaps, measurement gaps, dependencies, and a prioritized implementation backlog.
4. Execute: create evidence-backed content, information-architecture, entity, schema, internal-link, or measurement changes within the assigned scope.
5. Validate: verify rendered output, crawlability, canonical facts, schema truth, accessibility, locale consistency, analytics instrumentation, and baseline/query protocol.
6. Review: run `generative-engine-optimization-review` plus any SEO, schema, content, privacy, accessibility, security, or release gate triggered by the changes.
7. Document: record sources, owners, dates, observations, limitations, confounders, and explicit non-guarantees.
8. Deliver: provide the approved changes, evidence bundle, prioritized remaining backlog, measurement plan, and unresolved risks.

## Decision points
- If a material fact has conflicting sources, stop that claim or entity change and escalate to the accountable owner.
- If a proposed tactic has no documented human/crawler value beyond speculative model manipulation, remove or reframe it.
- If schema or metadata would assert facts not visibly supported by canonical content, block the change.
- If measurement lacks a baseline or reproducible query/observation method, do not approve performance claims.
- If an external authority signal would need to be fabricated or simulated, record the gap instead of implementing it.
- If a domain contract is affected, route to that specialist/review before release.

## Validation
- Canonical entity facts and material claims have inspectable sources and accountable owners.
- Rendered answers are accessible, crawlable, internally discoverable, and useful without AI-only behavior.
- Technical SEO, canonicalization, indexation, and structured data are validated where changed.
- Page content, metadata, schema, feeds, public profiles, and locale variants do not contradict one another.
- AI-search measurement includes dated baseline, query set, observation conditions, release annotations, confounders, and attribution limits.
- Independent GEO review has no unresolved blocking findings.

## Failure handling
- Do not silently continue when required canonical facts, evidence, or measurement inputs are unavailable.
- Failed SEO, schema, accessibility, analytics, privacy, security, localization, or review validation blocks completion for the affected scope.
- Unsupported or fabricated public claims must be removed, qualified, or escalated before delivery.
- If platform guidance cannot be verified, label the recommendation as uncertain and avoid externally visible guarantees.
- Destructive, privacy-sensitive, security-sensitive, or release actions still require the approvals defined by their owning contracts.

## Completion criteria
- The GEO scope is implemented or explicitly documented as deferred/blocked with owner and reason.
- Entity and claim sources are traceable and conflicts are resolved or escalated.
- Answer-ready content and technical changes have inspectable validation evidence.
- A dated measurement baseline and reproducible observation protocol exist before progress claims are made.
- Independent GEO review is complete and blocking findings are closed or carried as explicit release blockers.
- Delivery documentation separates verified facts, observations, hypotheses, limitations, and non-guarantees.

## Required lifecycle
Understand → Inspect → Plan → Execute → Validate → Review → Document → Deliver.
