# Runtime Parity Model

Runtime parity means that two supported runtimes preserve the same core
responsibilities, workflows, governance expectations, and delivery evidence.

## Parity dimensions

### Semantic parity

Agents, skills, commands, workflows, and reviews retain the same meaning.

### Capability parity

Each runtime can perform equivalent high-level engineering tasks.

### Governance parity

Both runtimes enforce the same contracts, quality gates, and review outcomes.

### Knowledge parity

Both runtimes consume the same canonical memory, ADRs, documentation, and
project context.

### Validation parity

Both runtimes have independent tests and explicit compatibility evidence.

## Allowed differences

- Invocation syntax
- Tool names
- File structure
- Runtime-specific metadata
- Execution ergonomics

## Forbidden differences

- Silent responsibility changes
- Missing mandatory review gates
- Different memory semantics
- Unrecorded capability gaps
- Unsupported release claims
