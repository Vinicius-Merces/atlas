# Technical Debt Model

Technical debt is a future cost created by a current technical condition.

## Debt categories

### Architecture debt

Unclear boundaries, duplicated capabilities, cyclic dependencies, or obsolete
system structure.

### Code debt

Duplication, complexity, weak abstractions, missing tests, or fragile behavior.

### Data debt

Poor ownership, inconsistent schemas, low data quality, or unsafe migrations.

### Platform debt

Outdated infrastructure, brittle pipelines, manual operations, or unsupported
runtime versions.

### Security debt

Known vulnerabilities, weak controls, excessive permissions, or missing threat
models.

### Documentation debt

Stale or missing architecture, operations, contracts, and onboarding guidance.

### Product debt

Behavior that remains confusing, inconsistent, inaccessible, or unsupported.

## Debt record

A useful debt item identifies:

- Evidence
- Impact
- Urgency
- Scope
- Owner
- Remediation path
- Cost of delay
- Verification
- Expiration or review date
