# Policy-as-Code Model

Policy-as-code converts stable governance requirements into executable checks.

## Suitable policies

- Required metadata
- Naming conventions
- Forbidden file locations
- Missing ownership
- Missing review dates
- Unsupported versions
- Required release artifacts
- Schema validity
- Dependency rules
- Required quality gates

## Unsuitable policies

- Product strategy
- Ambiguous architecture trade-offs
- Ethical judgment
- Unresolved legal interpretation
- Context-dependent UX decisions

## Policy behavior

Every policy should define:

- Objective
- Scope
- Rule
- Evidence
- Severity
- Failure message
- Exception process
- Owner
- Review cadence
