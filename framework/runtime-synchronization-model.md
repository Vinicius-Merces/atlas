# Runtime Synchronization Model

Runtime synchronization keeps runtime-specific adapters aligned with the
canonical ATLAS registry and contracts.

## Synchronization sources

- Registry collections
- Stable contracts
- Canonical commands
- Canonical workflows
- Canonical reviews
- Runtime support policy

## Generated outputs

- Runtime catalogs
- Runtime indexes
- Capability matrices
- Compatibility evidence
- Drift reports

## Synchronization rules

- Canonical files remain the source of truth.
- Generated files must be identifiable.
- Manual runtime guidance remains separate from generated catalogs.
- Drift must be detectable.
- Missing mappings must fail validation.
- Unsupported capabilities must be explicit.
