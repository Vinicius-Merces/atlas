# Compatibility Model

Compatibility describes whether ATLAS assets can be adopted, upgraded, or
executed without unexpected semantic or structural breakage.

## Compatibility dimensions

### Framework compatibility

Contracts, paths, registries, workflows, and canonical semantics remain usable.

### Runtime compatibility

Adapters map ATLAS concepts to supported runtime capabilities.

### Project compatibility

Project-specific memory, ADRs, rules, and customizations remain valid.

### Artifact compatibility

Packages, schemas, manifests, and automation remain internally consistent.

### Operational compatibility

Build, test, release, and validation procedures continue to function.

## Compatibility states

- **Supported**
- **Supported with limitations**
- **Experimental**
- **Deprecated**
- **Unsupported**
- **Unknown**

## Compatibility rule

Unknown compatibility must remain visible and must not be reported as supported.
