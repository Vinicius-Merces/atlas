# Documentation Architecture Model

Documentation should help users discover, understand, apply, operate, and evolve
ATLAS.

## Documentation layers

### Orientation

README, vision, concepts, terminology, and quick start.

### Adoption

Installation, bootstrap, blueprints, project onboarding, and migration.

### Reference

Agents, skills, workflows, contracts, reviews, schemas, commands, and adapters.

### Operations

Release, incident, observability, validation, packaging, and recovery.

### Governance

Principles, ADRs, policies, compatibility, deprecation, and maturity models.

### Examples

Reference implementations, sample memory, sample workflows, and reports.

## Documentation rules

- Every canonical concept has one primary location.
- Indexes link to canonical documents.
- Examples must be marked as examples.
- Deprecated guidance links to replacements.
- Commands and paths must be validated.
